# Padrões de página

Regras que **toda** página do site precisa seguir. Use como checklist antes de dar uma página como pronta.

## Regra de independência

Toda página de produto precisa funcionar **sozinha**, sem o visitante ter lido nenhuma outra antes.
Cada uma responde, por si só:

1. **O que é isso?**
2. **Pra quem é?**
3. **O que resolve na prática?**
4. **O que eu recebo?**
5. **Por que confiar?**

### Corolários explícitos do briefing
- ❌ **Core** não pode ser apresentado como "evolução do Run".
- ❌ **Scale** não pode ser apresentado como "Core + extras".
- ✅ Referências cruzadas só como **gatilho de upgrade no final** (ex.: Run → Core na seção
  "Quando o Run não basta").

## Estrutura narrativa padrão

```
Promessa → Dor/Inimigo → Mecanismo → Prova → CTA
```

## Acima da dobra (primeiros 5 segundos)

- **Headline**: O QUE faz + PRA QUEM + DIFERENCIAL
- **Subheadline** reforçando a promessa
- **1 CTA** claro e visível
- **Prova social rápida** (números ou logos)

## Princípios de conversão

- **1 objetivo por página**
- CTA repetido a cada **2–3 scrolls**
- **Objection handling** antes do CTA final
- **Urgência real** ("1 nova clínica/mês")
- Social proof **próximo ao CTA**

## Copywriting 2026

- Frases curtas, parágrafos de 1–2 linhas
- Linguagem do público, não interna
- **Benefício antes de feature**
- Contraste **Antes/Depois**
- **Pattern interrupt a cada scroll**: texto → número → imagem → depoimento → pergunta

## Confiança e redução de fricção

- Logos acima da dobra
- Números concretos (R$42M rastreado, 11.8x ROAS, 140+ clínicas)
- **Fotos reais** (não stock)
- Vídeo curto (1–2 min)
- Formulário simples (nome + WhatsApp)

## Blocos reutilizáveis entre páginas

Componentes que se repetem e devem ser construídos uma vez só:

| Bloco | Onde aparece |
|---|---|
| **Hero** (H1 + sub + CTA + visual) | Todas |
| **"Você se reconhece aqui?"** (lista de 4–6 dores) | Start, Full, Core, Scale, Run, Agendamento 10x, todas da Academy |
| **"O que resolve na prática"** (blocos alternados texto/imagem) | Todas as páginas de produto |
| **Timeline de etapas** (ETAPA N + duração + descrição) | Start, Full, Core, Scale |
| **Tabela Antes/Depois** | Start, Agendamento 10x, home |
| **Análise de mercado e posicionamento** (idêntica em Core e Scale) | Core, Scale |
| **CTA final fundo escuro + escassez** | Todas as páginas de produto |
| **Depoimentos de clientes** | Todas (decisão do briefing: repetir a mesma seção) |
| **Bloco "Sobre a Renke"** | Todas as páginas da Academy |

> 💬 Nota do briefing (Revena Core, seção Resultados):
> *"@Eduarda Tuorto aqui vamos repetir alguma seção de outra página? Acho que podemos colocar a
> mesma seção de depoimentos de clientes em todas as páginas"* — ou seja, **depoimentos = componente
> global**.

## CTA final padrão (páginas de produto Studio)

Fundo escuro, centralizado:

> **Limitado a 1 nova clínica por mês.**
> Cada projeto começa com diagnóstico. Não usamos template. Não terceirizamos.
>
> **Converse com a equipe. Em 90 dias, sua operação pode estar rodando. →**

## Formulários

| Página | Campos |
|---|---|
| **Home** | Nome · WhatsApp · Especialidade · Faturamento mensal → botão "Quero saber se faz sentido" |
| **Contato** | Nome · E-mail · WhatsApp · Interesse (seletor: Protocolo Revena / Renke Academy / Outro assunto) · Mensagem (opcional) → "Enviar" |
| **Faça Parte** | Nome · E-mail · WhatsApp · Área de interesse (seletor: Marketing/Performance, CRM/Comercial, Tecnologia/Automações, Design/Conteúdo, Outra) · Link do currículo ou portfólio → "Enviar currículo" |

**Princípio:** poucos campos, sem fricção.

## Checklist de publicação por página

- [ ] Uma única H1, com keyword principal
- [ ] Meta title e meta description únicos
- [ ] Schema aplicável
- [ ] Página se sustenta sem contexto de outras páginas
- [ ] CTA repetido a cada 2–3 scrolls
- [ ] Passou pelo [filtro de copy do WhatsApp](../01-estrategia/posicionamento-e-tom-de-voz.md#-filtro-obrigatório-de-copy)
- [ ] Nenhum [termo proibido](../01-estrategia/glossario-e-termos-proibidos.md)
- [ ] Todo conceito tem seu "na prática, isso significa..."
- [ ] Números conferidos contra a tabela consolidada de provas
- [ ] Imagens reais (sem stock genérico), com `alt` descritivo
- [ ] Mobile testado antes do desktop
